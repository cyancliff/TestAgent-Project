# 第5章 系统测试与实验分析
<!-- chapter_id: ch_5 -->

## 5.1 测试目标与测试环境

系统测试的目标是验证在线主流程、多模态离线链路和报告接入是否能够稳定运行。在线主流程测试关注用户认证、测评会话、答题提交、历史记录、报告展示、聊天关联和异常输入处理；多模态链路测试关注 CFI-V2 manifest、预处理、特征提取、bundle构建、训练、评估和在线真实推理；前端测试关注不同状态下页面是否能正确展示和恢复。

当前项目在 Windows 和 PowerShell 环境下开发，多模态训练环境已验证 torch、torchvision、torchaudio 和 CUDA 可用，GPU 为 NVIDIA GeForce RTX 4060 Laptop GPU。在线主系统支持本地开发和 Docker 部署，后端提供健康检查接口，前端通过Vite 开发服务器或容器入口访问。

测试范围既包括自动化测试，也包括实际 smoke 验证。项目 tests 目录包含认证、聊天、RAG、题目选择、问题清洗、多模态模型、多模态训练管线和大五报告 API 等测试文件；多模态在线 smoke 验证结果已归档到 reports/online_multimodal_smoke_20260425。

## 5.2 在线主系统功能测试

在线主系统测试首先验证用户从进入系统到完成测评的路径。用户登录后，系统能够检查是否存在未完成会话，并在有未完成会话时提示继续测评或修改答案；首次测评时，系统创建草稿并进入题目页面；用户逐题作答后，前端展示阶段进度、总进度和提交状态。

阶段提交测试重点关注数据一致性。系统需要确保每道题的选项合法，保存作答时间和得分，并在阶段完成时更新 submitted_stages。若用户刷新页面或重新进入系统，resume 接口能够返回已答题目和当前阶段，使前端恢复到正确状态。

历史记录和报告测试重点验证 completed 报告和 active 会话的区分。用户完成测评后，可以在历史页查看报告，重新进入详情页，也可以进入聊天页将报告作为上下文。删除会话时，系统需要同步清理答题记录、模块辩论结果和相关聊天引用，避免孤立数据残留。

从当前实现看，在线主流程已经形成较完整闭环。用户系统、ATMR 测评流程、自适应选题、异常作答检测、多智能体辩论、RAG、报告页和历史页均已完成，能够支持毕业设计演示和论文主体描述。

## 5.3 多模态实验设置

多模态实验围绕 CFI-V2 数据集展开。根据项目文档，当前实验使用官方划分，训练集 6000 条、验证集 2000 条、测试集 2000 条。输入视频经过抽帧、音频提取和转写后，分别生成 CLIP 视觉特征、CLIP 文本特征、wav2clip 音频特征以及工程版 bg_features。

模型训练采用 AGTN-MTL baseline。训练脚本读取 train 和 val manifest，解析对应 feature bundle，构建 PyTorch Dataset和 DataLoader，并在验证集上保存最优 checkpoint。评估脚本在测试集 bundle 上计算 MSE、MAE、ACC、PCC、CCC 和 R² 等指标。

评价指标中，MSE 和 MAE 衡量预测误差，ACC 在当前项目中按人格回归任务常用的 1-MAE 计算，PCC 衡量预测与真实标签之间的线性相关性，CCC 同时考虑相关性和数值一致性，R² 衡量模型相对标签均值基线的解释能力。对于人格分数回归任务，PCC、CCC和 R² 比单独的 ACC 更能反映模型是否捕捉到分数变化趋势。

## 5.4 多模态实验结果

项目首先进行了小样本闭环验证。train 20 / val 5 规模下，模型得到 MSE=0.004983、MAE=0.057872；train 100 / val 20规模下，模型得到 MSE=0.016520、MAE=0.100234。这两组结果的意义主要在于验证预处理、特征提取、bundle、训练和评估链路可以真实运行，而不是证明模型已经达到最终性能。

随后，项目完成 CFI-V2 全量 baseline 训练，并完成一轮调参。初始全量 baseline 在测试集上得到 MSE=0.019945、MAE=0.113552。调参后，当前在线默认 checkpoint 为 reports/night_lr1e4_drop02/agtn_mtl_lr1e4_drop02.pt，测试集结果为MSE=0.011543、MAE=0.086074、PCC=0.7062、CCC=0.6327、R²=0.4881。

| 实验 | 样本数 | MSE | MAE | ACC | PCC | CCC | R² |
|---|---:|---:|---:|---:|---:|---:|---:|
| 初始全量 baseline | 2000 | 0.0199 | 0.1136 | 0.8864 | 0.3422 | 0.1925 | 0.1154 |
| lr1e-4 / dropout 0.2 | 2000 | 0.0115 | 0.0861 | 0.9139 | 0.7062 | 0.6327 | 0.4881 |
| lr1e-4 / dropout 0.3 | 2000 | 0.0122 | 0.0885 | 0.9115 | 0.7062 | 0.5776 | 0.4609 |
| lr2e-4 / dropout 0.3 | 2000 | 0.0131 | 0.0916 | 0.9084 | 0.6684 | 0.5410 | 0.4196 |

从结果看，lr1e-4 / dropout 0.2 是当前最优版本。相较初始全量 baseline，它不仅降低了 MSE 和 MAE，也明显提高了PCC、CCC 和 R²，说明调参后模型对人格分数变化趋势的捕捉能力更强。当前 PCC=0.7062 已接近参考论文在 CFI-V2 上报告的PCC=0.7267，但 CCC 和 R² 仍低于原论文完整方法。因此，本文应表述为工程化 baseline 的调参最优版本，而不能声称完全复现原论文最终指标。

在线真实推理 smoke 验证显示，服务端已经能够对真实视频样本返回非占位分数。例如某次归档结果为 openness=0.4708、conscientiousness=0.4182、extraversion=0.3815、agreeableness=0.4902、neuroticism=0.3939。该结果说明多模态模型已经接入在线服务，并能生成大五人格报告。

## 5.5 结果分析与讨论

多模态实验结果表明，当前系统已经从占位推理进入真实模型推理阶段。小样本验证证明链路可运行，全量 baseline 证明模型可以在官方划分上完成训练和测试，调参结果则说明学习率和 dropout 对模型泛化能力有明显影响。对于毕业设计而言，这一阶段成果足以支撑“工程化 baseline 复现与系统接入”的论文表达。

同时，实验也暴露出若干限制。首先，当前在线 checkpoint 仍主要对应旧零填充 bg_features 版本，虽然工程版 256 维 bg_features已经实现，但需要重新生成 bundle 并重训后才能作为正式对照。其次，多任务损失尚未完整复现，当前 baseline 主要依赖主任务回归训练。再次，随机种子、单模态/多模态消融和更多数据质量分析仍不充分。

在系统层面，大五人格报告已经接入历史页、详情页和聊天上下文，这说明多模态结果不再只是离线实验表格，而是进入了用户可见的产品流程。但为了保证解释边界，系统只允许真实模型输出进入正式 AI 解读，失败结果或 scaffold 结果会被标记为不可用于对话。这一设计避免了用户误把占位分数理解为真实人格判断。

从 ATMR 与 Big Five 的关系看，二者不应简单相互验证。ATMR 来自问卷自陈，Big Five 来自视频外显行为线索，标签体系、数据来源和误差来源不同。本文将二者并列呈现，是为了让用户获得更多视角，而不是建立确定的映射关系。后续若要研究一致性，需要设计专门的数据采集和统计分析流程。

## 5.6 系统不足与改进方向

当前系统仍有若干不足。第一，数据库迁移和后台任务体系仍需正规化。当前多模态后台任务主要通过服务层和本地任务记录管理，适合毕设演示和本地开发，但如果面向真实多用户环境，需要引入更稳定的任务队列、任务重试和资源隔离机制。

第二，多模态模型仍需进一步补充实验。当前最重要的改进方向是使用新 bg_features 重新生成 bundle，训练一版与旧零填充版本对照；其次是补充多任务损失、单模态消融、多模态融合消融和多随机种子结果。只有这些实验完成后，论文才能更充分地讨论每个模块对最终性能的贡献。

第三，报告解释质量仍可继续打磨。虽然系统已经具备 RAG 和多智能体辩论，但心理测评文本需要在专业性、可读性和边界提示之间保持平衡。后续可以针对不同用户状态优化报告模板，增加失败状态说明、使用建议和非临床边界提示。

第四，系统安全和隐私仍需加强。心理测评和视频数据都属于敏感信息，正式部署时应进一步完善文件权限、数据脱敏、日志清理、访问审计和用户数据删除机制。本文初稿只对工程实现进行说明，隐私合规细节仍需在后续版本中补充。

需要说明的是，本文当前版本以系统实现和阶段性实验结果为主要依据。对于尚未完成的随机种子实验、单模态消融实验和新 bg_features 重训实验，正文中只保留为后续工作或待补充项，不将其写成已经完成的结论。这一处理可以避免论文初稿在表达上过度承诺，也便于后续根据真实实验记录继续替换和扩展。

## 5.7 本章小结

本章对系统测试和多模态实验进行了分析。在线主系统已经具备完整测评闭环，多模态子系统完成小样本验证、全量 baseline、调参和在线 smoke 验证。当前结果能够支撑毕业设计论文的系统实现和实验分析，但仍需在消融实验、任务队列、隐私保护和报告解释质量方面继续完善。

## 5.8 伦理边界与应用风险分析

心理测评系统天然涉及用户的自我认知、情绪状态和人格倾向，因此不能只从技术性能角度评价系统。即使模型指标较好，系统也不应给出医学诊断、就业筛选或人格定性的绝对判断。本文将系统定位为非临床辅助分析工具，所有报告都应服务于自我理解和后续咨询，而不是替代专业心理评估。

视频多模态人格预测还涉及额外风险。视频中的光照、镜头角度、背景噪声、说话主题、拍摄设备和用户临场状态都会影响模型输出。某个视频片段不能代表用户长期稳定人格，更不能被用于脱离语境的标签化判断。因此，系统在大五报告中保留模型版本、来源文件和结果性质，并将其作为“视频多模态线索”而非最终人格结论。

隐私保护同样需要重视。问卷答案、聊天记录、上传视频和人格报告都属于敏感数据。正式部署时，系统应提供更明确的数据保留策略、用户删除入口、文件访问控制和日志脱敏机制。当前毕业设计版本已经在用户所有权校验和随机文件名保存方面做了基础处理，但仍需要在论文后续版本中补充更完整的数据安全方案。

算法公平性也是潜在问题。多模态模型若主要在特定数据集、语言环境或文化背景下训练，可能对其他群体表现不稳定。因此，本文不将模型输出推广到所有场景，只在当前实验数据和工程条件下讨论其可用性。后续若要面向更广泛用户，应进行跨数据集、跨人群和跨场景验证。

从产品设计角度看，系统应鼓励用户把测评报告当作讨论材料，而不是人格标签。聊天咨询功能可以帮助用户围绕报告内容继续提问，但回答中也应提醒用户结合现实经历、长期表现和必要时的专业支持。这样的边界意识，是智能心理测评系统能否负责任落地的重要前提。
