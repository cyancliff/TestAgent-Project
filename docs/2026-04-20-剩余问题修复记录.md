# 2026-04-20 剩余问题修复记录

## 修复范围

本次修复对应上一轮 review 里剩下的两项问题：

1. 聊天会话切换测评后，上下文会串线。
2. `finish-stream` 仍在使用 query token 鉴权。

---

## 1. 聊天会话切换测评时的上下文串线

### 问题表现

原实现里，`update_chat_session()` 在切换 `assessment_session_id` 后会调用 `init_chat_with_context()`，但后者只删除旧的 `system` 消息，不删除旧的 `user/assistant` 消息。

这会导致同一个聊天会话里出现：

- 旧测评留下来的历史问答
- 新测评生成的系统上下文

模型会在后续对话里同时看到两套来源不同的上下文，属于明确的行为级错误。

### 修复方案

修改文件：

- `app/api/chat.py`

具体改动：

- 新增 `clear_chat_messages()`，统一负责按会话清理消息。
- `init_chat_with_context()` 增加 `reset_history` 参数。
- 当只是普通重建系统提示时，仍只清理 `system` 消息。
- 当检测到会话重新绑定到新的测评时，传入 `reset_history=True`，先清空整段聊天历史，再基于新测评重建系统提示。
- `clear` 接口也复用了新的清理函数，避免重复逻辑。

### 修复后的行为

- 重新绑定测评后，旧的 `user/assistant` 消息不会残留。
- 新系统提示只会基于当前测评构建。
- 单纯改标题不会误删既有聊天记录。

### 回归测试

新增文件：

- `tests/test_chat_api.py`

覆盖用例：

- `test_update_chat_session_clears_history_when_assessment_changes`
- `test_update_chat_session_title_change_preserves_existing_history`

验证点：

- 切换到新测评后，会话只保留新的 `system` 消息。
- 改标题时，会话历史保持不变。

## 2. `finish-stream` 统一为标准 Bearer 鉴权

### 问题表现

原实现中：

- `GET /api/v1/assessment/finish-stream`
- 通过 `token` query 参数手动收 JWT
- 不走全站统一的 `Depends(get_current_user)`

这样会带来几个问题：

- query token 更容易出现在浏览器历史、代理日志和访问日志里
- 认证方式和系统其他接口不一致
- 后续维护时更容易漏掉边界校验

### 修复方案

修改文件：

- `app/api/assessment/streaming.py`

具体改动：

- 删除 `token` query 参数解析逻辑。
- 删除手动 `JWT decode` 流程。
- 改为直接注入 `current_user: User = Depends(get_current_user)`。
- 后续业务逻辑统一使用 `current_user.id`。

### 修复后的行为

- 未登录访问会直接返回标准 `401 Not authenticated`。
- 已登录访问仍可正常建立 SSE 流并完成后续报告写回。

### 回归测试

新增文件：

- `tests/test_assessment_streaming_api.py`

覆盖用例：

- `test_finish_stream_requires_authentication`
- `test_finish_stream_uses_standard_authenticated_user`

验证点：

- 未认证请求会被 FastAPI/OAuth2 依赖挡住。
- 已认证请求仍能正常返回 `text/event-stream`。
- SSE 完成后报告内容仍会写回会话对象。
