# ATMR 无感知异常作答检测与可信度降权说明

更新时间：2026-04-30

## 1. 设计目的

ATMR 测评不再采用“异常后前台追问”的交互方式，而是改为：

> 前端无感知记录作答行为摘要，后台统一评估作答风险，并将风险转化为题级、维度级和整体测评可信度。

这样设计更适合正式测评系统：

- 不打断用户答题流程，避免用户因为被提示“异常”而改变后续作答。
- 不依赖用户对异常行为的主观解释，避免“乱填解释也能通过”的问题。
- 可以把作答质量控制包装为后台行为风险模型，技术含量更清晰。

论文中可以表述为：

> 为降低随意作答、机械作答和低质量作答对测评结论的影响，本文设计了一种无感知作答行为质量评估机制。系统在前端采集作答时长、首次交互延迟、鼠标行为摘要、选项变更次数和页面焦点变化等行为特征，并在后台构建多规则融合的作答风险模型。该机制不打断用户测评流程，而是将异常风险转化为题级可信度，并进一步影响维度级与整体测评可信度。

## 2. 前台行为摘要

系统只保存压缩后的行为统计值，不保存完整鼠标坐标轨迹。这样既能提供测评质量证据，也能减少数据量和隐私风险。

当前每题记录的行为摘要包括：

| 字段 | 含义 |
|------|------|
| `time_spent` | 该题总作答时长 |
| `first_action_latency` | 进入题目到第一次前台交互的时间 |
| `mouse_move_count` | 鼠标移动次数 |
| `mouse_path_length` | 鼠标移动路径长度摘要 |
| `pointer_down_count` | 点击或触控按下次数 |
| `option_change_count` | 选项变更次数 |
| `option_change_path` | 最近若干次选项变化路径 |
| `focus_blur_count` | 作答期间切出页面次数 |
| `idle_time` | 作答期间长时间无操作累计时长 |
| `rapid_click_flag` | 是否存在短时间连续点击 |

数据库字段：

- `answer_records.behavior_metrics`

接口字段：

- `/assessment/check-answer` 请求新增 `behavior_metrics`
- `/assessment/submit-stage` 每题答案新增 `behavior_metrics`
- `/assessment/report/{session_id}` 答题证据中返回 `behavior_metrics`

## 3. 后台风险规则

当前异常检测融合两类信号：传统作答模式信号 + 前台行为信号。

| 信号 | 触发条件 | 风险增量 | 说明 |
|------|----------|---------:|------|
| 作答时间明显过快 | `time_spent < avg_time * 0.10` | 70 | 明显低于题目平均阅读与判断时间 |
| 首次交互过快 | `first_action_latency` 极短 | 30 | 进入题目后几乎立刻点击 |
| 几乎无前台交互 | 作答较快，且鼠标移动次数和路径长度极低 | 20 | 识别缺少阅读/操作过程的快速作答 |
| 选项反复更改 | `option_change_count >= 4` | 25 | 识别犹豫或反复点击造成的不稳定答案 |
| 选项多次更改 | `option_change_count >= 2` | 12 | 轻度选项不稳定 |
| 频繁切出页面 | `focus_blur_count >= 3` | 25 | 识别测评过程中多次离开页面 |
| 切出页面 | `focus_blur_count >= 1` | 10 | 轻度离开页面 |
| 长时间无操作 | `idle_time` 超过题目平均时长的较大倍数 | 10 | 识别中断、挂机或注意力分散 |
| 短时间连续点击 | `rapid_click_flag = true` | 15 | 识别快速连点 |
| 连续同选项 | 最近 3 题均与当前题选择相同 | 35 | 识别机械式重复选择 |
| 极端选项集中 | 当前题为极端选项，且最近窗口极端选项比例不低于 `0.8` | 25 | 识别长期集中选择强烈同意/强烈不同意 |
| 近期异常密度高 | 最近 5 题中至少 2 题已被标记异常 | 20 | 识别短时间内连续低质量作答 |

风险分数记为：

```text
r_i = min(sum(rule_delta_i), 100)
```

其中 `r_i` 表示第 `i` 题的作答风险分数。若：

```text
r_i >= 50
```

则该题被标记为异常作答。

## 4. 单题可信度计算

单题可信度 `c_i` 由风险分数和异常状态共同决定。

当前实现逻辑为：

```text
c_i = clamp(1 - 0.0065 * r_i - 0.08 * z_i, 0.2, 1.0)
```

其中 `z_i` 表示该题是否被标记为异常。系统不会把某题的可信度降到 0，原因是 ATMR 的目标不是做主观动机判断，而是做测评质量控制。维度级与整体级可信度公式见 `docs/ATMR可信度模型与论文表达.md`。

## 5. 数据流

异常作答检测在系统中的流转如下：

```text
用户进入题目
  -> 前端记录作答时长、鼠标行为、选项变化、页面焦点变化等摘要
  -> 用户选择答案
  -> /assessment/check-answer 后台即时评估风险，不弹追问
  -> /assessment/submit-stage 后台基于行为摘要重新评估并入库
  -> 写入 answer_records.risk_score / risk_reasons / answer_confidence / behavior_metrics
  -> 汇总到 dimension_confidence 和 assessment_confidence
  -> 报告页展示风险原因、行为摘要、单题置信度和证据链
```

关键字段包括：

- `behavior_metrics`：前台作答行为摘要。
- `risk_score`：单题风险分数。
- `risk_reasons`：风险原因列表。
- `answer_confidence`：单题可信度。
- `dimension_confidence`：维度级可信度。
- `assessment_confidence`：整体测评可信度。

## 6. 为什么不再做异常追问

取消异常追问的理由：

1. 追问会打断测评流程，可能影响用户后续答题心态。
2. 用户解释质量本身难以可靠判断，低质量解释也可能伪装成合理解释。
3. 后台行为评定更容易形成可复现实验和论文方法。

因此本系统采用“无感知后台评定”的策略：

- 用户正常完成测评。
- 前端只采集行为摘要，不展示异常提示。
- 后端统一计算风险和可信度。
- 报告中透明展示风险原因和行为证据。

答辩时可以这样说：

> 我取消了前台异常追问，因为追问会干扰测评过程，也容易被用户主观解释绕过。现在系统采用无感知行为质量评估：前端只记录压缩后的行为摘要，后台统一计算作答风险，并把风险转化为报告可信度。这比简单提示用户“你异常了”更像一个完整的测评质量控制机制。

## 7. 当前边界

这套机制可以作为工程化质量控制和论文创新点，但仍需说明边界：

- 当前阈值来自工程经验和仿真实验，不是大规模真实样本统计得到。
- 它只能识别高风险作答模式，不能证明用户主观上一定在乱答。
- 系统只保存行为摘要，不保存完整鼠标坐标轨迹。
- 后续如果有真实作答数据，可以重新估计各行为特征的权重和异常阈值。

更稳妥的论文表述是：

> 本文提出的异常作答检测机制主要用于降低低质量作答对系统画像的影响，并为报告解释提供可信度依据。该机制并不对用户作答动机进行主观判断，而是从行为模式层面对测评证据进行风险标注与置信度调整。
