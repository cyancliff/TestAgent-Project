# 开发者日志

更新时间：2026-04-20

这份文档给维护者看，不重复写产品介绍，而是说明当前仓库真实状态、最近关键演进，以及继续开发时最容易踩坑的地方。

## 1. 当前仓库快照

### 在线主系统

在线主系统已经是一个可运行的完整产品骨架，主流程包括：

- 注册登录
- 测评草稿、恢复、阶段提交
- A / T / M / R 四阶段答题
- 自适应选题与异常作答检测
- 模块辩论与综合报告
- 历史记录与 AI 咨询

对维护者来说，这条线当前更像“稳定维护 + 小幅补强”，而不是“重搭框架”。

### 多模态子系统

多模态现在不应再被视为“只有接口的占位功能”。当前已经具备：

- CFI-V2 manifest 构建
- 视频预处理
- CLIP 特征提取
- wav2clip 特征提取
- feature bundle 组装
- AGTN-MTL baseline 训练、评估、推理
- 可恢复的全量长任务 runner

目前真正没完成的是“把真实结果接回主系统”。

## 2. 最近最重要的演进

### 2.1 多模态最小闭环已经做实

新增的关键入口：

- `multimodal_personality/training/baseline.py`
- `scripts/train_agtn_mtl.py`
- `scripts/eval_agtn_mtl.py`
- `scripts/infer_agtn_mtl.py`
- `scripts/run_full_multimodal_pipeline.py`

这意味着当前仓库已经支持从 bundle 直接进入训练，而不是只停留在接口和预处理层。

### 2.2 当前环境已验证 GPU 可用

本地已验证环境：

- Python `3.14`
- `torch 2.11.0+cu126`
- `torch.cuda.is_available() == True`
- `NVIDIA GeForce RTX 4060 Laptop GPU`

所以现在不是“没有 GPU 跑不了”，而是“已经可以跑，只是还没把最终结果接回在线系统”。

### 2.3 wav2clip 兼容问题已经修掉

`wav2clip` 在较新的 `librosa` 版本下会遇到接口兼容问题，当前已在 `multimodal_personality/feature_extractors/wav2clip_extractor.py` 做兼容修复。

这件事要记住，因为后续如果重建环境，很容易再次踩到这个坑。

## 3. 当前多模态真实状态

### 已完成的小样本验证

1. `train 20 / val 5`
   - `mse=0.004983`
   - `mae=0.057872`
2. `train 100 / val 20`
   - `mse=0.016520`
   - `mae=0.100234`

这两次结果说明：

- 工程闭环已经成立
- 模型不是纯占位
- 但这还不是正式实验终稿

### 全量任务状态

当前仓库已经具备全量长任务入口：

- `scripts/run_full_multimodal_pipeline.py`

默认产物目录：

- `reports/full_multimodal_pipeline/`

关键日志：

- `reports/full_multimodal_pipeline/stderr.log`
- `reports/full_multimodal_pipeline/stdout.log`

这个 runner 的价值在于：

- 可恢复
- 不会重复处理已完成的样本
- 可以把预处理、特征、bundle、训练、评估串成一条线

## 4. 当前最容易误判的地方

### 误判 1：在线多模态已经是真实推理

不是。

`app/services/multimodal_personality_service.py` 当前仍返回 `scaffold-v1` 和 `0.50` 占位分数。也就是说：

- 预处理是真实的
- 离线训练是真实的
- 但在线服务返回的分数还不是真实 checkpoint 推理结果

### 误判 2：主系统还没成型

也不是。

主系统现在缺的不是主流程，而是：

- 多模态结果挂接
- 论文实验收口
- 工程治理补强

### 误判 3：当前最重要的是继续做 UI

不是。

当前最重要的是先把全量多模态结果拿到手，否则后面任何在线接入、报告展示和论文结果都缺真实依据。

## 5. 继续开发时的建议顺序

推荐按这个顺序继续：

1. 等全量多模态 baseline 跑完。
2. 固定 checkpoint 与 `val / test` 指标。
3. 把真实 checkpoint 接到在线服务。
4. 把多模态结果挂到会话、报告、历史记录。
5. 最后再做调参和论文对比分析。

## 6. 当前仍需补的工程点

这些不是“马上阻塞开发”，但仍然是真实技术债：

- 数据库迁移还没有完全切到 Alembic 主导
- 后台任务体系仍可继续正规化
- 多模态结果尚未正式持久化到主系统实体关系中
- 在线报告尚未展示 Big Five 结果

## 7. 运行中的注意事项

如果仓库里正在跑全量多模态长任务：

- 不要删除 `uploads/multimodal_personality/artifacts`
- 不要删除 `reports/full_multimodal_pipeline`
- 不要随意关闭黑色 `python.exe` 宿主窗口

长任务是否还在推进，以日志为准，不要只看终端窗口有没有输出。

- `README.md`
