# 开发者日志

更新时间：2026-06-24

这份文档给维护者看，不重复写产品介绍，而是说明当前仓库真实状态、最近关键演进，以及继续开发时最容易踩坑的地方。

## 2026-06-24：证据约束型静态多 Agent 工作流增强

- 在不改变测评主流程和数据库结构的前提下，为 ATMR 报告接口补充 `agent_state`、`agent_trace` 和 `report_critic` 派生字段。
- 当前定位为“证据约束型静态多 Agent 工作流”：测评过程继续使用确定性快速路径，Agent 只在报告生成、证据状态说明和安全边界审查等低频高价值环节体现。
- 报告页新增“智能分析过程”展示区块，用于说明测评结果读取、证据状态构建、多角色分析、策略选择、安全审查和最终报告生成状态。
- 本增强不引入新的 LLM 调用、外部服务、数据库迁移或动态逐题 Agent，便于部署到合作公司网站时保持稳定性。

## 1. 当前仓库快照

### 在线主系统

在线主系统已经是一个可运行的完整产品骨架，主流程包括：

- 注册登录
- 测评草稿、恢复、阶段提交
- A / T / M / R 四阶段答题
- 自适应选题与异常作答检测
- ATMR-CAT 自适应选题、无感知作答行为风险评估与可信度降权
- 模块辩论与综合报告
- 历史记录与 AI 咨询
- 独立的大五人格报告、Big Five RAG 解读和双报告聊天上下文

对维护者来说，ATMR 主流程已经稳定，大五人格报告也已进入主系统；后续更像“报告质量打磨 + 工程治理 + 实验收口”，而不是“重搭框架”。

### 多模态子系统

多模态现在不应再被视为“只有接口的占位功能”。当前已经具备：

- CFI-V2 manifest 构建
- 视频预处理
- CLIP 特征提取
- wav2clip 特征提取
- feature bundle 组装
- AGTN-MTL baseline 训练、评估、推理
- 可恢复的全量长任务 runner

真实 checkpoint 已经接回在线 service，并已通过“大五人格”报告进入历史页、详情页和聊天上下文。关键 `ACC / PCC / CCC / R²` 指标已经补齐，`bg_features` 也已有工程版实现；当前真正没完成的是基于新 `bg_features` 的重训对照、更多消融实验和后台任务/迁移治理。

## 4. 当前最容易误判的地方

### 误判 1：只要 Web 服务启动，多模态就一定是真实推理

不一定。

本地已验证环境中，`app/services/multimodal_personality_service.py` 已经能完成真实 checkpoint 推理。但它依赖本地多模态环境、checkpoint 和重型模型依赖。也就是说：

- 预处理是真实的
- 离线训练是真实的
- 本地在线 service smoke 已经是真实 checkpoint 推理
- 轻量部署环境若缺依赖或 checkpoint，仍可能触发回退分数

### 误判 2：主系统还没成型

也不是。

主系统现在缺的不是主流程，而是：

- 实验结果收口
- 工程治理补强
- 报告解释质量和演示文案继续打磨

### 误判 3：当前最重要的是继续做 UI

不是。

当前最重要的是补齐实验指标，并继续打磨大五人格报告的解读质量、失败状态和演示口径。

## 5. 继续开发时的建议顺序

推荐按这个顺序继续：

1. 补齐 `PCC / CCC / R²` 等关键指标和实验表格。
2. 继续打磨大五人格报告解读质量、失败重试和演示文案。
3. 继续评估 `bg_features`、多任务损失和随机种子实验是否值得做。
4. 收口数据库迁移、后台任务、部署说明和演示材料。
