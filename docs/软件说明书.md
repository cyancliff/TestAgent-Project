# ATMR 智能心理测评系统软件说明书

更新时间：2026-06-01

## 1. 软件概述

ATMR 智能心理测评系统是一套面向心理测评、人格倾向分析和测评后咨询的 Web 系统。系统以 ATMR 问卷测评为主线，结合自适应选题、异常作答检测、多智能体辩论、RAG 知识检索和视频多模态人格预测，为用户生成结构化测评报告，并支持基于报告上下文的 AI 咨询。

系统当前由三条能力线组成：

1. 在线 ATMR 主系统：负责用户注册登录、问卷作答、阶段提交、报告生成、历史记录和 AI 咨询。
2. 大五人格视频报告：负责上传视频后的 Big Five 五维预测、报告生成、AI 解读和聊天上下文关联。
3. 离线多模态子系统：负责视频预处理、特征提取、AGTN-MTL baseline 训练、评估和推理，为在线系统提供多模态辅助证据。

本软件定位为研究与教学演示系统，不应替代临床诊断、医学判断或专业心理咨询结论。

## 2. 适用对象

- 普通用户：完成 ATMR 心理测评、查看报告、上传视频生成大五人格报告、进行测评后咨询。
- 管理员：维护题库质量参数、查看测评可信度、查看报告质量和实验结果。
- 开发与部署人员：负责本地开发、Docker 部署、多模态实验运行、测试和维护。

## 3. 运行环境

### 3.1 在线主系统

推荐环境：

- 操作系统：Windows + PowerShell，或可运行 Docker 的服务器环境
- Python：`3.10` 及以上
- Node.js：可运行 Vue 3 + Vite 项目
- 数据库：
  - 本地开发默认可使用 SQLite
  - Docker / 部署环境推荐 PostgreSQL 15
- 后端框架：FastAPI
- 前端框架：Vue 3 + Vite

### 3.2 离线多模态子系统

多模态训练与真实推理建议在单独环境运行：

- Windows + PowerShell
- NVIDIA GPU 与可用 CUDA 环境
- 已安装 `ffmpeg`
- 已安装 `requirements_multimodal.txt` 中的依赖
- 已准备 CFI-V2 数据或符合项目 manifest 规范的数据

轻量 Web 部署不要求安装完整多模态训练依赖。若部署环境未挂载 checkpoint 或缺少多模态依赖，系统会进入回退路径，但该结果不应作为真实多模态分析结论展示。

- `frontend/package.json`：前端依赖与构建脚本

## 5. 安装与启动

### 5.1 本地开发启动

安装后端依赖：

```powershell
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements_full.txt
python -m pip install -r requirements_feature.txt
Copy-Item .env.example .env
```

启动后端：

```powershell
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

新开一个 PowerShell 终端启动前端：

```powershell
Set-Location frontend
npm install
npm run dev
```

默认访问地址：

- 前端：`http://127.0.0.1:5173`
- 后端：`http://127.0.0.1:8000`
- 健康检查：`http://127.0.0.1:8000/health`

### 5.2 Docker Compose 启动

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

默认容器组成：

- `db`：PostgreSQL 数据库
- `backend`：FastAPI 后端
- `frontend`：Nginx + Vue 静态站点

启动后检查：

```powershell
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=50 frontend
```

默认只暴露前端入口。若需要直接访问 Swagger，可在 `docker-compose.yml` 的 `backend` 服务中显式暴露 `8000:8000`。

## 6. 环境变量说明

常用环境变量如下：

| 变量名 | 说明 |
| --- | --- |
| `APP_ENV` | 运行环境，开发环境通常为 `development` |
| `AUTO_CREATE_TABLES` | 是否启动时自动建表，开发环境默认启用 |
| `DATABASE_URL` | 数据库连接字符串，配置后优先使用 |
| `DB_USER` / `DB_PASSWORD` / `DB_HOST` / `DB_PORT` / `DB_NAME` | PostgreSQL 分项配置 |
| `SECRET_KEY` | JWT 签名密钥，生产环境必须设置强随机值 |
| `ADMIN_USERNAMES` | 管理员用户名列表，默认包含 `admin` |
| `DEEPSEEK_API_KEY` | DeepSeek 模型密钥 |
| `DEEPSEEK_CHAT_MODEL` | 聊天模型名称 |
| `DEEPSEEK_ANALYSIS_MODEL` | 报告分析模型名称 |
| `DEEPSEEK_RAG_MODEL` | RAG 解读模型名称 |
| `MULTIMODAL_CHECKPOINT_PATH` | 多模态 checkpoint 路径 |
| `MULTIMODAL_DEVICE` | 多模态推理设备，可设为 `auto`、`cpu` 或 `cuda` |
| `MICRO_EXPRESSION_ENABLED` | 是否启用微表情辅助模块 |

首次部署时应从 `.env.example` 复制生成 `.env`，再按实际环境修改密钥、数据库和模型配置。

## 7. 功能说明

### 7.1 用户认证

系统支持用户注册、登录、JWT 鉴权、头像上传和昵称修改。登录成功后，前端会保存访问令牌，并在后续请求中自动携带认证信息。令牌失效或接口返回 `401` 时，前端会清理本地登录状态并跳转登录页。

### 7.2 ATMR 测评

ATMR 测评流程支持：

- A / T / M / R 四阶段作答
- 测评草稿保存与恢复
- 阶段提交
- ATMR-CAT 自适应选题
- 异常作答检测
- 可信度降权
- 维度置信度计算
- 题目证据链记录
- 综合报告生成

报告内容包括维度分数、可信度提示、异常作答提示、解释边界和综合分析。报告用于辅助用户理解自我倾向，不作为医学或临床诊断依据。

### 7.3 大五人格视频报告

用户可上传视频生成独立的大五人格报告。报告内容包括：

- Big Five 五维分数
- 雷达图和分数条
- 维度简析
- 模态质量摘要
- 预测置信度
- ATMR 与 Big Five 一致性提示
- 基于 Big Five RAG 知识库的 AI 解读

大五人格报告与 ATMR 报告并列存在，不会被自动融合成单一结论。聊天页面可同时关联一份 ATMR 报告和一份大五人格报告作为咨询上下文。

### 7.4 AI 咨询

AI 咨询支持基于报告上下文进行追问。系统会读取用户选择的 ATMR 报告和大五人格报告，并结合知识库证据生成回答。若未配置模型密钥，报告和咨询中的 AI 解读能力会受到限制。

### 7.5 历史记录

历史记录页按报告类型组织用户历史数据，支持查看：

- ATMR 测评记录
- ATMR 报告详情
- 大五人格视频报告
- 相关聊天记录入口

## 8. 管理端说明

管理端入口为：

```text
/admin
```

只有管理员用户可以访问管理端。管理员由 `ADMIN_USERNAMES` 环境变量控制，命中配置的用户会被标记为 `admin`。

管理端第一版包括：

1. 管理首页
   - 用户数
   - ATMR 测评数
   - 已完成报告数
   - 平均整体可信度
   - 异常作答比例
   - 低可信报告数
   - 大五报告数量
   - 当前模型版本摘要
2. 题库质量
   - 按维度、关键词、启用状态筛选题目
   - 查看题目难度、区分度、平均作答时间和异常率
   - 修改题库轻量参数与启用状态
3. 报告质量
   - 查看 ATMR 报告和答题证据
   - 查看大五人格报告、质量摘要、置信度和一致性分析
4. 实验结果
   - 查看本地已有实验产物
   - 展示 ATMR-CAT、可信度加权、多模态消融和 `bg_features` 相关实验摘要

管理端不负责触发训练、删除用户、删除报告或执行高风险数据操作。

## 9. 离线多模态工作流

多模态子系统主要用于研究复现、训练评估和真实 checkpoint 推理。推荐先跑小样本闭环，再运行全量任务。

安装依赖：

```powershell
python -m pip install -r requirements_multimodal.txt
```

构建 CFI-V2 manifest：

```powershell
python scripts/build_cfi_v2_manifest.py --config multimodal_personality/configs/cfi_v2.example.yaml --phase all
```

运行最小闭环示例：

```powershell
python scripts/preprocess_cfi_v2_from_manifest.py --manifest multimodal_personality/data/cfi_v2/manifests/train_manifest.json --limit 100
python scripts/preprocess_cfi_v2_from_manifest.py --manifest multimodal_personality/data/cfi_v2/manifests/val_manifest.json --limit 20

python scripts/build_clip_feature_jobs.py --manifest multimodal_personality/data/cfi_v2/manifests/train_manifest.json
python scripts/extract_clip_features.py --jobs multimodal_personality/data/cfi_v2/train_feature_jobs.json --device cuda
python scripts/extract_wav2clip_features.py --jobs multimodal_personality/data/cfi_v2/train_feature_jobs.json

python scripts/build_multimodal_feature_bundles.py --manifest multimodal_personality/data/cfi_v2/manifests/train_manifest.json --limit 100
python scripts/build_multimodal_feature_bundles.py --manifest multimodal_personality/data/cfi_v2/manifests/val_manifest.json --limit 20

python scripts/train_agtn_mtl.py --train-manifest multimodal_personality/data/cfi_v2/manifests/train_manifest.json --val-manifest multimodal_personality/data/cfi_v2/manifests/val_manifest.json --train-limit 100 --val-limit 20 --device cuda
```

运行全量长任务：

```powershell
python scripts/run_full_multimodal_pipeline.py --train-device cuda --clip-device cuda
```

长任务支持断点恢复。运行时不要删除 `uploads/multimodal_personality/artifacts` 和对应的 `reports/` 产物目录。

## 10. 数据与安全

系统涉及用户账号、测评作答、报告内容、上传头像和视频文件。使用和部署时应注意：

- 生产环境必须设置强随机 `SECRET_KEY`。
- 生产数据库密码不应使用示例值。
- 模型 API 密钥应通过 `.env` 或部署平台密钥管理注入，不要写入公开文档。
- 管理端可查看完整报告，真实上线前应补充操作审计和更细粒度的数据脱敏。
- 上传文件应限制大小、类型和访问范围。
- 心理测评结果应展示解释边界，不应宣称临床诊断效力。
- 本地实验产物、临时导出文件和一次性生成脚本不应写入公开说明文档。

## 12. 常见问题

### 12.1 登录后接口返回 401

可能原因：

- token 已过期
- 后端重启导致开发环境临时 `SECRET_KEY` 改变
- 前端仍保存旧登录状态

处理方式：

```powershell
# 重新设置固定 SECRET_KEY 后重启后端，再重新登录
```

也可在浏览器中清理本地站点数据后重新登录。

### 12.2 Docker 后端无法连接数据库

检查：

```powershell
docker compose ps
docker compose logs --tail=100 db
docker compose logs --tail=100 backend
```

重点确认 `DATABASE_URL`、`DB_PASSWORD`、数据库容器健康状态和网络连接。

### 12.3 AI 解读为空或失败

常见原因：

- 未配置 `DEEPSEEK_API_KEY`
- 模型名称配置错误
- 外部模型服务不可用
- 网络连接异常

处理方式是检查 `.env` 中模型密钥和模型配置，并查看后端日志。

### 12.4 多模态推理返回回退结果

常见原因：

- 未安装多模态依赖
- 未安装 `ffmpeg`
- checkpoint 路径不存在
- GPU 环境不可用
- 上传视频无法完成预处理

处理方式是检查 `MULTIMODAL_CHECKPOINT_PATH`、`MULTIMODAL_DEVICE`、依赖安装和后端日志。演示真实推理时建议使用已验证的本地 GPU 环境。
