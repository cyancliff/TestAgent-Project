# 多模态参考论文研究与复现成果汇报

更新时间：2026-04-24

本文档用于向导师汇报本项目中“视频多模态人格预测”方向的研究理解、复现过程与当前成果。内容既说明参考论文的核心方法，也如实说明当前复现与论文原始实现之间的对齐程度和差异。

## 1. 研究背景与本课题中的定位

本项目的主体是一个基于 ATMR 问卷、异常作答检测、多智能体辩论和 RAG 辅助分析的智能心理测评系统。为了避免系统只依赖问卷自陈数据，我希望引入一条补充证据链：从视频中提取视觉、音频和语言信息，对受测者进行 Big Five 人格预测，再将其作为问卷结果之外的辅助人格画像。

因此，多模态部分在本课题中的作用不是替代现有 ATMR 测评主线，而是提供一条独立、可解释、可扩展的辅线能力。更具体地说：

1. ATMR 主线负责问卷式心理测评、报告生成与咨询交互。
2. 多模态辅线负责从短视频中预测 Big Five 五维人格分数。
3. 后续目标是将两条证据链并列呈现，而不是简单做数值级强行融合。

### 2.2 论文研究目标

这篇论文的目标是：给定一段人物短视频，同时分析视频画面、音频和转写文本，最终预测该人物的 Big Five 五维人格分数：

1. 开放性 `Openness`
2. 尽责性 `Conscientiousness`
3. 外向性 `Extraversion`
4. 宜人性 `Agreeableness`
5. 神经质 `Neuroticism`

与很多只关注单模态特征的方法不同，这篇论文强调：

1. 不仅要提取单模态特征，还要显式建模跨模态关联特征。
2. 不仅要做最终多模态预测，还要让单模态分支在训练时承担辅助监督任务。
3. 不仅要处理顺序信息，还要用图结构与注意力机制捕捉更长距离的时序依赖。

### 2.3 论文核心方法理解

我对论文核心方法的理解可以概括为 4 个部分。

#### 2.3.1 三类核心输入特征

论文最终要融合的，不是原始视频本身，而是三类中间特征：

1. `scene-description association feature`
   含义是场景帧与一组人格描述词之间的关联程度。
2. `scene-audio association feature`
   含义是视频场景和音频片段之间的关联程度。
3. `text feature`
   含义是转写文本经过句子级编码和时序建模后的语言特征。

#### 2.3.2 自适应图 Transformer 网络

论文的一个核心创新是将图卷积和 Transformer 自注意力结合起来，分别处理：

1. 视频帧之间的关系
2. 音频 patch 之间的关系

这样做的动机是：人格线索往往不是局部瞬时信号，而是跨时间片段逐渐形成的模式，因此需要比普通 RNN 更强的长程依赖建模能力。

#### 2.3.3 融合模块

论文没有采用最简单的特征拼接，而是使用了带残差的通道注意力融合模块。其作用是：

1. 让模型自动学习不同模态、不同维度对人格预测的重要性。
2. 用残差连接减少特征融合过程中的信息损失。

#### 2.3.4 多任务联合学习

论文的训练过程除了一个多模态主任务外，还有多个单模态辅助任务。作者认为这样可以：

1. 增强训练稳定性
2. 降低过拟合风险
3. 迫使每个单模态分支都学到与人格相关的有效信号

### 2.4 论文实验结论

论文在 `CFI-V2` 和 `UDIVA v0.5` 两个数据集上做了实验，作者报告其方法优于已有方法。以 `CFI-V2` 为例，论文中给出的代表性指标为：

- `ACC = 0.9196`
- `PCC = 0.7267`
- `CCC = 0.7085`
- `R² = 0.5226`

这说明论文的主要贡献不仅体现在模型结构设计上，也体现在实验对比和消融实验上，尤其证明了以下两点：

1. 自适应图 Transformer 比常见序列模型更适合该任务。
2. 多任务损失与跨模态关联特征设计确实能提升效果。

## 3. 我的复现思路与工程策略

### 3.1 复现目标

我没有直接把论文代码生硬塞进主系统，而是采用“先独立复现、再逐步接入”的策略。当前目标分为三个层次：

1. 先做离线最小闭环：确保从原始视频到 Big Five 分数可以完整跑通。
2. 再做全量 baseline：在 `CFI-V2` 的官方划分上完成训练、验证和测试。
3. 最后接入在线服务：让项目主系统可以调用真实 checkpoint，而不是只保留占位接口。

### 3.2 为什么采用这种策略

这样做主要有三个原因：

1. 论文复现依赖较重，包含 `ffmpeg`、`whisper`、`CLIP`、`wav2clip`、`PyTorch CUDA` 等，直接并入主系统风险较高。
2. 论文模型本身是研究性模块，而主系统已经是一个相对稳定的业务工程，两者需要解耦。
3. 如果不先拿到真实 checkpoint 和真实结果，后续报告页接入和论文实验分析都没有依据。

### 3.3 当前采用的数据与环境

本次复现主要围绕 `CFI-V2` 数据集展开，保持论文中的官方划分：

- `train = 6000`
- `val = 2000`
- `test = 2000`

已验证环境如下：

- Windows + PowerShell
- Python `3.14`
- `torch 2.11.0+cu126`
- `torchvision 0.26.0+cu126`
- `torchaudio 2.11.0+cu126`
- GPU：`NVIDIA GeForce RTX 4060 Laptop GPU`
- `torch.cuda.is_available() == True`

为了向导师汇报时保持严谨，下面把“已经对齐”和“尚未完全对齐”的部分明确区分。

| 项目 | 当前状态 |

| 视频、音频、文本三模态输入 | 已对齐 |

### 5.2 尚未完全对齐的部分

| 项目 | 当前状态 |
|------|----------|

### 5.3 对当前成果的准确定位

因此，当前最准确的说法是：

1. 已完成论文路线的工程化 baseline 复现。

4. 但当前仍不应宣称“已经严格复现论文全部方法与最终指标”。

## 6. 当前实验结果

### 6.1 小样本闭环验证结果

为确保工程链路可用，我先进行了小样本验证：

1. `train 20 / val 5`
   - `MSE = 0.004983`
   - `MAE = 0.057872`
2. `train 100 / val 20`
   - `MSE = 0.016520`
   - `MAE = 0.100234`

这两组结果说明：

1. 模型已经不是占位结构，而是真实可训练可推理。
2. 从预处理到训练评估的整条链路已经贯通。
3. 小样本规模下，模型已经能够输出可解释的五维分数。

### 6.2 全量 baseline 结果

在 `CFI-V2` 全量数据上，我已经完成一次正式 baseline 训练：

- `train = 6000`
- `val = 2000`
- `test = 2000`

产物目录位于：

- `reports/full_multimodal_pipeline/`

关键结果如下：

- `best_epoch = 1`
- `val mse = 0.019289`
- `val mae = 0.110833`
- `test mse = 0.019945`
- `test mae = 0.113552`

从训练历史看，模型在第 1 个 epoch 就取得了最佳验证结果，后续训练损失继续下降但验证集不再提升，说明当前 baseline 已经出现一定程度的过拟合倾向，这也反映出后续还有较大的调参空间。

### 6.3 在线服务真实推理结果

在全量 checkpoint 生成之后，我又进行了在线服务 smoke run 验证。现在服务端已经可以对真实视频样本返回非占位的人格分数，例如某一真实样本返回：

- `openness = 0.5707`
- `conscientiousness = 0.5111`
- `extraversion = 0.4918`
- `agreeableness = 0.5585`
- `neuroticism = 0.5284`

这说明多模态结果已经具备进入主系统的基础，而不是停留在离线实验阶段。
